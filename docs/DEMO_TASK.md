# 增量演示任务：异常运单筛选与原因展示

## 任务标题

在现有运单系统中增加异常运单筛选与原因展示

## 业务背景

运营人员已经使用现有运单工作台跟踪运输状态。当前系统虽然保存了异常类型和异常原因，但页面无法单独筛选异常运单，也无法查看具体异常原因。运营仍需逐条检查运单，容易遗漏需要优先处理的问题。

本次目标不是重做系统，而是在现有代码、数据和交互上完成一个可审查、可测试的小增量。

## 可直接用于 CoStrict 的任务描述

```text
请在当前项目关联的存量运单系统中，完成“异常运单筛选与原因展示”增量需求，不要从零重写项目。

业务背景：
现有运单列表已支持关键词搜索、运输状态筛选、基础统计和运单详情。数据 public/data/shipments.js 中已有 exceptionType 和 exceptionReason 字段，但页面尚未使用。运营需要优先识别并处理异常运单。

功能要求：
1. 在现有筛选区域增加“仅看异常运单”选项，异常判定为 exceptionType 非空。
2. 异常筛选必须能与现有关键词搜索、运输状态筛选组合使用，结果数量和空状态保持正确。
3. 在运单列表中为异常运单展示异常类型和异常原因；非异常运单不展示异常标记或虚构异常信息。
4. 在运单详情中同步展示异常类型和异常原因，保证列表与详情数据一致。
5. 保持现有页面布局可用，在常见桌面和窄屏下均能阅读异常信息，不破坏原有搜索、状态筛选和详情交互。

工程与验收：
1. 优先复用 public/lib/shipment-utils.js 中的共享筛选逻辑，保持浏览器和 Node.js 测试使用同一实现。
2. 为“仅看异常”、异常与关键词/状态组合筛选、空结果和详情数据一致性补充确定性测试。
3. 保留原有测试并确保全部通过；不得通过删除或放宽旧测试掩盖回归。
4. 更新 README，说明新增能力、操作方式和测试命令。
5. 在独立任务分支上提交真实代码变更并创建 Pull Request，不要直接提交到 main，不要修改任务范围外的功能。
6. 最终列出修改文件、测试结果、页面验证结果和 PR 链接。

明确不在本次范围：
- 不增加 CSV 导出、后端写入、真实客户数据、登录权限或生产部署。
- 不重写整个页面，不引入新的第三方框架或外部服务。
```

## 人工验收口径

### 基线确认

1. 启动 `main` 基线，页面存在 12 张运单。
2. 页面没有“仅看异常运单”选项，列表和详情不显示异常原因。
3. `npm test` 的存量测试通过。

### 增量功能确认

1. 选择“仅看异常运单”，结果只包含 `exceptionType` 非空的 4 张运单：`BW20261123001`、`BW20261123003`、`BW20261123006`、`BW20261123008`。
2. 在异常筛选基础上选择“派送中”，只剩 `BW20261123008`。
3. 在异常筛选基础上搜索“林悦”，只剩 `BW20261123006`。
4. 输入不存在的客户，出现空状态；重置后恢复完整列表。
5. 异常运单的列表和详情均展示一致的非空异常类型与异常原因。
6. 非异常运单不出现异常标记或异常原因。
7. 窄屏下筛选控件和异常信息仍可读、可操作。

### 工程与交付确认

1. `npm test` 全部通过，旧测试没有被删除或放宽。
2. PR 只包含本需求相关代码、测试和文档变更，没有全量重写或无关格式化。
3. 页面、测试和 PR 证据对应同一个提交。
4. 审核通过后才合并；未合并前仅称“功能已在代码 PR 中”，不称“已更新 main”。
